Welcome to the study pack! I've broken down the project into three core pillars: Backend, Frontend, and the Configurator App.

Inside each guide, you'll find a clear, step-by-step breakdown of how the most important files work. I'll explain not just what the code does, but why it was designed that way, using the same conversational teaching style we've used throughout the project.

Recommended Order

1. Backend First

  • Start with server.py and base.py to understand the foundation.
  • Then, walk through the handlers (like facts.py and state.py) to see how that foundation is used in practice.
  • Pay attention to the consistent API envelopes, caching strategies, and strict validation.

2. Frontend Second

  • Start with loader.js and container.js to see how the widget bootstraps and manages state.
  • Look at renderers.js to understand how raw data becomes UI.
  • Focus on the embed model, live polling logic, and phase transitions.

3. Configurator Third

  • Explore how config.html acts as the bridge for operators.
  • See how CSS variables allow powerful, live-preview theming without rewriting code.
  • Understand how the embed snippet is generated dynamically.

Key Concepts to Master

  • Read-only & Cacheable: Why the API uses standard envelopes and varying TTLs based on data volatility.
  • Future-proof: Why the contract is shaped to support a robust data backend (like ClickHouse) later.
  • Embeddability: Why the widget uses a single script tag with data-* attributes.
  • Vanilla JS: Why avoiding massive frameworks makes the widget lighter and more universally compatible.
